## 1. 모듈과 패키지의 개념

### 1.1 모듈(Module)이란?

**모듈(Module)**은 파이썬 코드가 담긴 파일(`.py`)입니다. 함수, 클래스, 변수 등을 정의하여 재사용할 수 있게 합니다.

```python
# math_utils.py (모듈 파일)
def add(a, b):
    return a + b

def multiply(a, b):
    return a * b

PI = 3.14159
```

#### 모듈을 사용하는 이유

- **코드 재사용**: 한 번 작성한 코드를 여러 곳에서 사용
- **코드 조직화**: 관련 기능을 그룹화
- **네임스페이스**: 변수명 충돌 방지
- **유지보수**: 코드 수정이 용이

### 1.2 패키지(Package)란?

**패키지**는 여러 모듈을 그룹화한 디렉토리입니다. `__init__.py` 파일이 있는 디렉토리가 패키지가 됩니다.

```
my_package/          # 패키지 디렉토리
├── __init__.py      # 패키지 초기화 파일 (필수)
├── module1.py       # 모듈 1
├── module2.py       # 모듈 2
└── subpackage/      # 서브패키지
    ├── __init__.py
    └── module3.py
```

### 1.3 패키지 vs 모듈

| 구분 | 모듈 | 패키지 |
|------|------|--------|
| **형태** | 단일 `.py` 파일 | 디렉토리 |
| **필수 파일** | 없음 | `__init__.py` |
| **용도** | 관련 기능을 하나의 파일에 | 여러 모듈을 그룹화 |
| **예시** | `utils.py` | `utils/` |

## 2. 모듈 생성하기

### 2.1 간단한 모듈 생성

```python
# calculator.py
def add(a, b):
    """덧셈 함수"""
    return a + b

def subtract(a, b):
    """뺄셈 함수"""
    return a - b

def multiply(a, b):
    """곱셈 함수"""
    return a * b

def divide(a, b):
    """나눗셈 함수"""
    if b == 0:
        raise ValueError("0으로 나눌 수 없습니다")
    return a / b

# 모듈 레벨 변수
VERSION = "1.0.0"
AUTHOR = "Your Name"
```

### 2.2 모듈 실행 코드 분리

```python
# calculator.py
def add(a, b):
    return a + b

def subtract(a, b):
    return a - b

# 모듈이 직접 실행될 때만 실행되는 코드
if __name__ == "__main__":
    # 테스트 코드
    print(add(1, 2))      # 3
    print(subtract(5, 3))  # 2
```

### 2.3 모듈 임포트하기

#### import 문
```python
# 전체 모듈 임포트
import calculator

result = calculator.add(1, 2)
print(calculator.VERSION)
```

#### from-import 문
```python
# 특정 함수/변수만 임포트
from calculator import add, subtract

result = add(1, 2)  # calculator. 없이 사용
```

#### 별칭 사용
```python
# 모듈에 별칭 부여
import calculator as calc

result = calc.add(1, 2)

# 함수에 별칭 부여
from calculator import add as plus

result = plus(1, 2)
```

## 4. `__init__.py` 파일의 역할

### 4.1 기본 역할

`__init__.py` 파일은 디렉토리를 패키지로 인식하게 만듭니다.

#### 빈 `__init__.py` (최소 구성)
```python
# my_package/__init__.py
# 빈 파일이어도 패키지로 인식됨
```

### 4.2 패키지 초기화

패키지가 임포트될 때 실행되는 코드를 작성할 수 있습니다.

```python
# my_package/__init__.py
print("패키지가 임포트되었습니다!")

# 패키지 레벨 변수
VERSION = "0.1.0"
AUTHOR = "Your Name"
```

### 4.3 패키지 레벨 임포트

패키지에서 자주 사용하는 모듈/클래스를 직접 임포트할 수 있게 합니다.

```python
# my_package/__init__.py
from .utils import greet, add
from .models import User

# 패키지를 임포트하면 자동으로 사용 가능
__all__ = ['greet', 'add', 'User']
```

**사용 예시:**
```python
# 사용하는 쪽
import my_package

# __init__.py에서 임포트한 것들을 바로 사용 가능
my_package.greet("홍길동")
user = my_package.User("김철수")
```

### 4.4 패키지 초기화 함수

```python
# my_package/__init__.py
def initialize():
    """패키지 초기화 함수"""
    print("패키지 초기화 완료")

def get_version():
    """버전 정보 반환"""
    return "0.1.0"
```

## 5. 패키지 임포트 방법

### 5.1 기본 임포트

#### 전체 패키지 임포트
```python
import my_package

# 사용: my_package.module.function()
my_package.utils.greet("홍길동")
```

#### 패키지 내 모듈 임포트
```python
from my_package import utils
from my_package import models

# 사용
utils.greet("홍길동")
user = models.User("김철수")
```

#### 특정 함수/클래스 임포트
```python
from my_package.utils import greet, add
from my_package.models import User

# 사용
greet("홍길동")
result = add(1, 2)
user = User("김철수")
```

### 5.2 별칭(Alias) 사용

```python
import my_package as mp
from my_package import utils as u

mp.utils.greet("홍길동")
u.greet("홍길동")
```

### 5.3 모든 것 임포트 (권장하지 않음)

```python
from my_package import *  # 권장하지 않음

# __all__이 정의되어 있으면 그것만 임포트됨
```

## 7. 패키지 내 모듈 간 임포트

### 7.1 상대 임포트 (Relative Import)

패키지 내부에서 다른 모듈을 임포트할 때 사용합니다.

```python
# my_package/utils.py
def helper():
    return "helper function"

# my_package/models.py
from .utils import helper  # 같은 패키지 내 utils 모듈

class User:
    def __init__(self):
        self.helper = helper()
```

### 7.2 상대 임포트 문법

```python
# 현재 패키지 내 모듈
from .module import something

# 상위 패키지
from ..parent_module import something

# 같은 레벨의 다른 패키지
from ..sibling_package import something

# 서브패키지
from .subpackage.module import something
```

### 7.3 절대 임포트 (Absolute Import)

```python
# my_package/models.py
from my_package.utils import helper  # 절대 경로

class User:
    def __init__(self):
        self.helper = helper()
```

### 7.4 상대 vs 절대 임포트

| 구분 | 상대 임포트 | 절대 임포트 |
|------|-----------|-----------|
| **문법** | `from .module import` | `from package.module import` |
| **장점** | 패키지 이름 변경 시 유연 | 명확하고 이해하기 쉬움 |
| **권장** | 패키지 내부에서만 | 일반적으로 권장 |

## 8. 패키지 구조 예제

```python
from .basic import add, subtract
```

```python
from calculator import add, power

result1 = add(1, 2)      # 3
```

### 9.2 `setup.py` 작성

```python
from setuptools import setup, find_packages

setup(
    name="my_package",
    version="0.1.0",
    author="Your Name",
    description="패키지 설명",
    packages=find_packages(),  # 자동으로 패키지 찾기
    python_requires=">=3.8",
    install_requires=[
        "requests>=2.28.0",
    ],
)
```

## 10. 네임스페이스 패키지 (Namespace Package)

### 10.1 네임스페이스 패키지란?

`__init__.py` 파일 없이도 패키지로 인식되는 방식입니다. (Python 3.3+)

```
namespace_pkg/
├── part1/
│   └── module1.py
└── part2/
    └── module2.py
```

### 10.2 사용 예시

```python
# part1과 part2가 같은 네임스페이스에 있음
from namespace_pkg.part1 import module1
from namespace_pkg.part2 import module2
```

## 12. 패키지 개발 모범 사례

### 12.1 `__all__` 사용

패키지에서 공개할 항목을 명시합니다.

```python
# my_package/__init__.py
from .utils import greet, add
from .models import User

__all__ = ['greet', 'add', 'User']  # from package import * 시 이것만 임포트
```

### 12.2 버전 관리

```python
# my_package/__init__.py
__version__ = "0.1.0"
__version_info__ = (0, 1, 0)
```

### 12.3 문서화

```python
# my_package/__init__.py
"""
My Package - 패키지 설명

이 패키지는 다음과 같은 기능을 제공합니다:
- 유틸리티 함수
- 데이터 모델
- 서비스 클래스
"""

__version__ = "0.1.0"
```

### 12.4 순환 임포트 방지

#### 나쁜 예 (순환 임포트)
```python
# module1.py
from module2 import function2

# module2.py
from module1 import function1  # 순환 임포트!
```

#### 좋은 예
```python
# module1.py
def function1():
    from module2 import function2  # 함수 내부에서 임포트
    return function2()

# 또는 공통 모듈로 분리
```

### 12.5 패키지 초기화 최소화

`__init__.py`에서 무거운 작업을 피하고, 필요할 때만 임포트합니다.

```python
# my_package/__init__.py
# 나쁜 예: 모든 것을 즉시 임포트
from .heavy_module import HeavyClass  # 무거운 임포트

# 좋은 예: 지연 임포트
def get_heavy_class():
    from .heavy_module import HeavyClass
    return HeavyClass
```

### 12.6 `__init__.py`에서 Import 방식 선택

`__init__.py`에서 패키지 내부 모듈을 import하는 방식은 두 가지가 있습니다. 패키지의 목적과 사용 패턴에 따라 적절한 방식을 선택해야 합니다.

#### 방식 1: 모듈 노출 (Module Exposure)

모듈 자체를 패키지 레벨에서 접근 가능하게 합니다.

```python
# my_package/__init__.py
from . import stringutils
from . import numberutils
from . import dateutils

__all__ = ['stringutils', 'numberutils', 'dateutils']
```

**사용법:**
```python
import my_package as mp

# 모듈을 통해 함수 접근
mp.stringutils.reverse_string("Hello")
mp.numberutils.to_money(1000)
mp.dateutils.to_date("2024-01-01")
```

**장점:**
- ✅ 네임스페이스가 명확함 (어느 모듈의 함수인지 알 수 있음)
- ✅ 모듈 단위로 접근 가능
- ✅ 모듈 내부 구조를 명확히 표현
- ✅ 네임스페이스 충돌 방지

**단점:**
- ❌ 타이핑이 길어짐 (`mp.stringutils.reverse_string()`)
- ❌ 패키지 사용자가 내부 구조를 알아야 함
- ❌ 사용이 다소 번거로움

#### 방식 2: 함수 직접 노출 (Function Exposure)

자주 사용하는 함수를 패키지 레벨에서 직접 접근 가능하게 합니다.

```python
# my_package/__init__.py
from .stringutils import reverse_string
from .numberutils import to_money, to_percent, to_comma
from .dateutils import to_date

__all__ = [
    'reverse_string',
    'to_money',
    'to_percent',
    'to_comma',
    'to_date'
]
```

**사용법:**
```python
import my_package as mp

# 패키지 레벨에서 직접 접근
mp.reverse_string("Hello")
mp.to_money(1000)
mp.to_date("2024-01-01")
```

**장점:**
- ✅ 사용이 간단하고 직관적
- ✅ 공개 API를 명확히 정의 (`__all__` 사용)
- ✅ 패키지 레벨에서 직접 접근 가능
- ✅ 타이핑이 짧아짐

**단점:**
- ❌ 네임스페이스가 평평해짐
- ❌ 함수 이름 충돌 가능성
- ❌ 모듈 구조가 숨겨짐
- ❌ 많은 함수를 노출하면 네임스페이스 오염

#### 방식 3: 하이브리드 방식 (Hybrid Approach)

자주 사용하는 함수는 직접 노출하고, 모듈도 접근 가능하게 합니다.

```python
# my_package/__init__.py
"""
My package for my project
"""
# 자주 사용하는 함수는 직접 노출
from .stringutils import reverse_string
from .numberutils import to_money
from .dateutils import to_date

# 모듈도 접근 가능하도록
from . import stringutils
from . import numberutils
from . import dateutils

__all__ = [
    # 함수 직접 노출
    'reverse_string',
    'to_money',
    'to_date',
    # 모듈 노출
    'stringutils',
    'numberutils',
    'dateutils'
]

__version__ = "0.1.0"
__author__ = "Your Name"
```

**사용법:**
```python
import my_package as mp

# 간단한 사용 (자주 쓰는 함수)
mp.reverse_string("Hello")
mp.to_money(1000)

# 모듈 단위 접근 (다른 함수가 필요할 때)
mp.stringutils.reverse_string("Hello")
mp.numberutils.to_percent(0.15)  # 직접 노출되지 않은 함수
```

**장점:**
- ✅ 유연성: 간단한 사용과 세밀한 제어 모두 가능
- ✅ 사용자 선택권 제공
- ✅ 점진적 접근 가능

**단점:**
- ❌ `__init__.py`가 복잡해질 수 있음
- ❌ 두 가지 방식이 혼재되어 혼란 가능

#### 패키지 유형별 권장 방식

##### 1. 유틸리티 패키지 → 함수 직접 노출 권장

```python
# my_package/__init__.py
"""
유틸리티 함수 모음 패키지
"""
from .stringutils import reverse_string
from .numberutils import to_money, to_percent, to_comma
from .dateutils import to_date

__all__ = [
    'reverse_string',
    'to_money',
    'to_percent',
    'to_comma',
    'to_date'
]

__version__ = "0.1.0"
```

**이유:**
- 유틸리티 함수는 자주 사용되므로 간단한 접근이 유리
- `__all__`로 공개 API를 명확히 정의
- 사용자가 패키지 내부 구조를 몰라도 됨

##### 2. 구조화된 대규모 패키지 → 모듈 노출 권장

```python
# my_package/__init__.py
"""
대규모 구조화된 패키지
"""
from . import database
from . import models
from . import services
from . import utils

__all__ = ['database', 'models', 'services', 'utils']
```

**이유:**
- 모듈별로 기능이 명확히 구분됨
- 네임스페이스 충돌 방지
- 대규모 패키지에 적합
- 모듈 단위로 관리 용이

##### 3. 프레임워크/라이브러리 → 하이브리드 방식 권장

```python
# my_package/__init__.py
"""
프레임워크 패키지
"""
# 주요 클래스/함수 직접 노출
from .core import BaseClass, main_function
from .utils import helper_function

# 서브모듈도 접근 가능
from . import database
from . import models

__all__ = [
    'BaseClass',
    'main_function',
    'helper_function',
    'database',
    'models'
]
```

**이유:**
- 주요 기능은 쉽게 접근
- 세부 기능은 모듈을 통해 접근
- 유연성과 편의성의 균형

#### 실제 예제 비교

```python
# 예제 1: 모듈 노출 방식
# my_package/__init__.py
from . import stringutils, numberutils, dateutils

# 사용
import my_package as mp
result = mp.stringutils.reverse_string("Hello")  # 길지만 명확

# 예제 2: 함수 직접 노출 방식
# my_package/__init__.py
from .stringutils import reverse_string
from .numberutils import to_money

# 사용
import my_package as mp
result = mp.reverse_string("Hello")  # 짧고 간단

# 예제 3: 하이브리드 방식
# my_package/__init__.py
from .stringutils import reverse_string
from . import stringutils, numberutils

# 사용
import my_package as mp
result1 = mp.reverse_string("Hello")  # 직접 접근
result2 = mp.stringutils.reverse_string("Hello")  # 모듈 접근
result3 = mp.numberutils.to_percent(0.15)  # 모듈 접근
```

#### 선택 가이드

| 상황 | 권장 방식 | 이유 |
|------|----------|------|
| 유틸리티 함수 모음 | 함수 직접 노출 | 간단한 사용이 중요 |
| 대규모 구조화 패키지 | 모듈 노출 | 네임스페이스 관리 중요 |
| 프레임워크/라이브러리 | 하이브리드 | 유연성과 편의성 모두 필요 |
| 작은 프로젝트 | 함수 직접 노출 | 단순함이 우선 |
| 팀 프로젝트 | 모듈 노출 | 명확성과 일관성 중요 |

#### 주의사항

1. **과도한 Import 방지**
   ```python
   # ❌ 나쁜 예: 모든 것을 import
   from .module1 import *
   from .module2 import *
   
   # ✅ 좋은 예: 필요한 것만 선택적으로 import
   from .module1 import function1, function2
   ```

2. **순환 Import 주의**
   ```python
   # __init__.py에서 import할 때 순환 참조 주의
   # 각 모듈이 서로를 참조하지 않도록 설계
   ```

3. **`__all__` 명시**
   ```python
   # 공개 API를 명확히 정의
   __all__ = ['public_function1', 'public_class1']
   ```

4. **지연 Import 고려**
   ```python
   # 무거운 모듈은 필요할 때만 import
   def get_heavy_class():
       from .heavy_module import HeavyClass
       return HeavyClass
   ```

## 14. 패키지 임포트 문제 해결

### 14.1 ModuleNotFoundError

**문제:**
```python
ModuleNotFoundError: No module named 'my_package'
```

**해결:**
- 패키지가 `sys.path`에 있는지 확인
- `PYTHONPATH` 환경 변수 설정
- 개발 모드로 설치: `pip install -e .`

### 14.2 상대 임포트 오류

**문제:**
```python
ImportError: attempted relative import with no known parent package
```

**해결:**
- 스크립트로 직접 실행하지 말고 모듈로 실행: `python -m package.module`
- 절대 임포트 사용

### 14.3 순환 임포트

**문제:**
```python
ImportError: cannot import name 'X' from partially initialized module
```

**해결:**
- 임포트 순서 변경
- 함수/클래스 내부에서 임포트
- 공통 모듈로 분리

## 16. 요약

### 핵심 개념

1. **모듈**: `.py` 파일로 코드를 재사용 가능하게 함
2. **패키지**: `__init__.py`가 있는 디렉토리로 여러 모듈을 그룹화
3. **서브패키지**: 패키지 내부의 패키지
4. **표준 라이브러리**: Python에 내장된 모듈들 (math, datetime, random, os, sys, json, re 등)

### 패키지 생성 단계

1. 디렉토리 생성
2. `__init__.py` 파일 생성
3. 모듈 파일 추가
4. 필요시 `setup.py` 작성

### 임포트 방법

- **전체 패키지**: `import package`
- **모듈**: `from package import module`
- **함수/클래스**: `from package.module import function`
- **상대 임포트**: `from .module import something`

### 모범 사례

- ✅ `__all__`로 공개 API 명시
- ✅ 버전 정보 관리
- ✅ 문서화
- ✅ 순환 임포트 방지
- ✅ 테스트 코드 작성

### 주의사항

- ⚠️ `__init__.py`는 패키지 인식에 필수 (Python 3.3 이전)
- ⚠️ 상대 임포트는 패키지 내부에서만 사용
- ⚠️ 순환 임포트 주의
- ⚠️ 무거운 임포트는 지연 로딩
