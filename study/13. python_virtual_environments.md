## 1. 가상 환경이란?

### 1.1 가상 환경의 개념

**가상 환경(Virtual Environment)**은 프로젝트별로 독립적인 Python 환경을 만드는 도구입니다. 각 프로젝트의 패키지를 격리하여 관리할 수 있습니다.

### 1.2 가상 환경이 필요한 이유

- **패키지 버전 충돌 방지**: 프로젝트마다 다른 버전 사용 가능
- **의존성 관리**: 프로젝트별 패키지 목록 관리
- **시스템 Python 보호**: 시스템 Python을 깨끗하게 유지
- **재현 가능한 환경**: 동일한 환경 재현 가능

## 2. venv 모듈 사용법

### 2.1 가상 환경 생성

```bash
# Python 3.3+ 내장
python -m venv venv

# 또는
python3 -m venv venv

# 특정 Python 버전 지정
python3.9 -m venv venv
```

### 2.2 가상 환경 구조

```
venv/
├── bin/          # Linux/Mac (스크립트)
│   ├── activate
│   ├── python
│   └── pip
├── Scripts/      # Windows (스크립트)
│   ├── activate
│   ├── python.exe
│   └── pip.exe
├── lib/          # 패키지 저장
└── pyvenv.cfg    # 설정 파일
```

## 3. 가상 환경 활성화/비활성화

### 3.1 Windows

```bash
# 활성화
venv\Scripts\activate

# 비활성화
deactivate
```

### 3.2 Linux/Mac

```bash
# 활성화
source venv/bin/activate

# 비활성화
deactivate
```

### 3.3 활성화 확인

```bash
# 프롬프트에 (venv) 표시됨
(venv) $ python --version
(venv) $ which python  # Linux/Mac
(venv) $ where python  # Windows
```

## 4. 패키지 설치 및 관리

### 4.1 패키지 설치

```bash
# 가상 환경 활성화 후
pip install package_name

# 특정 버전
pip install package_name==1.2.3

# 버전 범위
pip install "package_name>=1.0,<2.0"
```

### 4.2 패키지 목록 확인

```bash
# 설치된 패키지 목록
pip list

# 패키지 정보
pip show package_name
```

### 4.3 패키지 제거

```bash
pip uninstall package_name
```

## 5. requirements.txt 관리

### 5.1 requirements.txt 생성

```bash
# 현재 환경의 패키지 목록 저장
pip freeze > requirements.txt
```

### 5.2 requirements.txt 내용 예시

```txt
Flask==2.3.0
requests==2.31.0
pandas==2.0.0
numpy==1.24.0
```

### 5.3 requirements.txt에서 설치

```bash
# requirements.txt의 패키지 설치
pip install -r requirements.txt
```

### 5.4 requirements.txt 구조화

```txt
# requirements/base.txt
Flask==2.3.0
requests==2.31.0

# requirements/dev.txt
-r base.txt
pytest==7.4.0
black==22.0.0

# requirements/prod.txt
-r base.txt
gunicorn==20.1.0
```

## 6. 다른 가상 환경 도구

### 6.1 virtualenv

```bash
# 설치
pip install virtualenv

# 생성
virtualenv venv

# 활성화 (venv와 동일)
source venv/bin/activate  # Linux/Mac
venv\Scripts\activate     # Windows
```

### 6.2 conda

```bash
# 가상 환경 생성
conda create -n myenv python=3.9

# 활성화
conda activate myenv

# 패키지 설치
conda install package_name

# 비활성화
conda deactivate
```

### 6.3 poetry

```bash
# 프로젝트 초기화
poetry init

# 가상 환경 생성 및 패키지 설치
poetry install

# 패키지 추가
poetry add package_name

# 가상 환경 활성화
poetry shell
```

## 7. 실전 예제

### 7.1 새 프로젝트 설정

```bash
# 1. 프로젝트 디렉토리 생성
mkdir my_project
cd my_project

# 2. 가상 환경 생성
python -m venv venv

# 3. 가상 환경 활성화
# Windows
venv\Scripts\activate
# Linux/Mac
source venv/bin/activate

# 4. 패키지 설치
pip install flask requests

# 5. requirements.txt 생성
pip freeze > requirements.txt
```

### 7.2 기존 프로젝트 복원

```bash
# 1. 프로젝트 디렉토리로 이동
cd my_project

# 2. 가상 환경 생성
python -m venv venv

# 3. 가상 환경 활성화
source venv/bin/activate  # Linux/Mac
# 또는
venv\Scripts\activate      # Windows

# 4. requirements.txt에서 설치
pip install -r requirements.txt
```

### 7.3 .gitignore 설정

```gitignore
# 가상 환경 제외
venv/
env/
ENV/
.venv/

# Python 캐시
__pycache__/
*.pyc
*.pyo
*.pyd

# 환경 변수
.env
.env.local
```

## 8. 주의사항

### 8.1 가상 환경을 Git에 커밋하지 않기

```bash
# .gitignore에 추가
venv/
env/
```

### 8.2 requirements.txt는 커밋하기

```bash
# requirements.txt는 버전 관리에 포함
git add requirements.txt
git commit -m "Add requirements.txt"
```

### 8.3 가상 환경 경로 문제

```bash
# 절대 경로 사용 시 문제 발생 가능
# 상대 경로 사용 권장
python -m venv ./venv
```

## 9. 요약

### 핵심 개념

1. **가상 환경**: 프로젝트별 독립 Python 환경
2. **venv**: Python 3.3+ 내장 모듈
3. **활성화/비활성화**: `activate`/`deactivate`
4. **requirements.txt**: 패키지 목록 관리

### 주요 명령어

- **생성**: `python -m venv venv`
- **활성화**: `source venv/bin/activate` (Linux/Mac), `venv\Scripts\activate` (Windows)
- **비활성화**: `deactivate`
- **패키지 설치**: `pip install package_name`
- **목록 저장**: `pip freeze > requirements.txt`
- **목록 설치**: `pip install -r requirements.txt`

### 모범 사례

- ✅ 프로젝트마다 가상 환경 사용
- ✅ requirements.txt 관리
- ✅ 가상 환경은 Git에 제외
- ✅ 명확한 가상 환경 이름 사용
